# 下一阶段设计：受控执行状态分叉

> 执行状态：第一阶段 task 5 开发实验已完成。实际协议、结果与后续判断见
> [受控滑落实验结论](../results/controlled_slip_baseline/结论.md)。

## 当前结果排除了什么

训练时随机丢当前图像没有让 R7 稳定超过同容量 C1。六个开发 cell 中，R7−C1 最大只有 +6.67 pp，差分中的差最大只有 +3.33 pp；预登记要求两项都至少 +10 pp。last-valid-frame 在两个 3-query 条件中得到 +10 pp 点估计，并能达到对应 R7 的成功数。

因此下一步不继续堆 residual history 的训练种子，也不立即安装失败诊断、双路记忆和更新门控。当前首要问题是评测没有制造可辨识的隐藏执行状态；架构复杂度不是已经被证明的瓶颈。

## 第一阶段：只改环境协议，不改模型

先比较现有四个模型：

| 模型 | 当前盲区输入 | 可用过去信息 |
|---|---|---|
| B2-zero | 全零双相机 + 当前本体状态 | 无 |
| B2-LVF | 最后有效双相机 + 当前本体状态 | 单帧缓存 |
| C1 | 全零双相机 + 当前本体状态 | 同容量当前帧适配器，没有过去视觉 |
| R7 | 全零双相机 + 当前本体状态 | 最多 8 条过去视觉转移与时间 |

每个 episode 从同一个 simulator state 分叉：

1. 策略完成抓取，并在有效画面中确认物体在夹爪内。
2. control 分支保持物体；slip 分支把物体确定性移动到固定、可重抓的位置。
3. 至少保留一个有效 query 观察干预结果，再让双相机缺失。
4. 在首个盲区 query 尽量匹配两分支的机器人本体状态。
5. control 的正确行为是继续放置；slip 的正确行为是返回并重新抓取。

这个 MVP 首先回答“任何形式的视觉记忆是否必要”。B2-LVF 是必须保留的强基线：如果它已经与 R7 相当，就说明单帧缓存足够，还不需要学习式多步记忆。

### 扩大前门槛

- 干预前 action prefix 哈希完全一致。
- 抓取与滑落结果都在相机缺失前被观察到。
- oracle 接触信息只用于构造与审计，不输入策略。
- 首个盲区 query 的机器人状态最大绝对差低于固定阈值。
- 10 个 pair 的 smoke 中，control/slip 物体位姿分离率和干预重放率均为 100%。

通过后才运行 3 tasks × 20 initial states × 2 branches，共 120 条轨迹/模型。仍先使用 seed11 开发集。R7 相对 C1 和 B2-LVF 的配对恢复率都达到 +10 pp 且 95% 区间下界大于零，才补训练种子和 held-out。

## 第二阶段：先做可解码性诊断

如果协议通过、R7 仍不能恢复，先冻结策略并检查历史 token 是否编码了以下隐藏状态：

- `object_in_gripper`；
- `slip_observed`；
- 当前阶段是 continue-place 还是 regrasp；
- 最后一次动作的视觉结果与预期是否一致。

训练轻量 probe，只作为诊断，不接入策略。标签来自 simulator oracle，但不能作为策略输入。

- probe 能解码、策略仍失败：问题在读取和动作路由，再测试门控或查询 token。
- probe 不能解码：问题在历史表示，先改 transition encoder。
- B2-LVF 已解决：保持简单帧缓存，停止学习式历史分支。

## 第三阶段：一次只改一个模块

只有第二阶段显示表示瓶颈时，才增加 `Outcome token`：

```text
r_i = [f(o_i), a_i, f(o_{i+1}) - f(o_i), Δx_i, Δt_i]
z_i = MLP(LayerNorm(r_i))
```

输入仍是最多 8 条已经执行的转移。压缩器读取的 token 分组固定为：

```text
[current image tokens, language tokens, current state token]
                         ↓ query
[transition_1 outcome token ... transition_8 outcome token]
                         ↓
                  action expert tokens
```

第一版不加任务/执行双路、不加失败分类器、不加可写记忆。唯一变化是把原来的视觉转移拼接改成显式动作—结果差分 token，并保留参数匹配的 C1-outcome 控制：使用当前图像复制出的伪 before/after，参数量与层数完全一致。

若 Outcome token 在受控分叉上稳定有效，再做下一项消融：

1. 最近执行记忆与早期任务记忆分路；
2. query 根据当前可见性选择读取哪一路；
3. 最后才加入失败类型与选择性更新。

每一步都保留上一版、同容量当前帧版和 B2-LVF，不同时安装多个模块。

## 数据怎么获得

不需要等待真实失败数据。LIBERO simulator 可以从同一初始状态和相同动作前缀生成配对轨迹：保存抓取后的 simulator state，复制为 control/slip 两个分支，固定物体位姿扰动，再继续 rollout。训练集只使用开发任务和开发 init；held-out init 在模块与阈值冻结后才读取。

恢复监督不能只包含“失败发生了”。需要记录：

- 干预前后物体位姿与抓取状态；
- 策略实际执行动作和结果；
- 是否返回重抓、重抓是否成功、最终任务是否成功；
- 每个 policy query 看到了哪些相机帧；
- control/slip pair 的前缀一致性和首个盲区状态差。

这批数据既能做闭环评测，也能训练 Outcome token 的自监督下一状态/接触变化辅助目标。先验证评测可辨识，再决定是否生成大规模训练集。
