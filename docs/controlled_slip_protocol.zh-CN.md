# 受控滑落配对协议

状态：`IMPLEMENTED-PROTOCOL-SMOKE`。这是后续闭环实验的可辨识性合同，不是已完成的滑落实验结果。

## 要回答的问题

策略已经看到物体被抓住，随后物体在相机缺失前发生确定性滑落。进入盲区时，control 与 slip 两条轨迹的机器人本体状态近似一致，但物体真实状态不同。比较策略是否继续放置或转向重新抓取，才能检验执行历史是否提供当前输入无法替代的信息。

## 配对单位

每个 pair 固定：

- LIBERO task、initial-state index、episode seed；
- 从 reset 到干预前的实际 action prefix；
- 首次确认抓取成功的观测 query；
- 干预时刻和随后双相机缺失的 query；
- 推理随机种子。

control 分支不移动物体；slip 分支在同一 simulator step 将已抓物体平移到预先固定的可重抓位置。两条分支随后都缺失双相机观测。

## 扩大实验前的硬门槛

1. 干预前 action prefix 哈希完全一致。
2. 抓取成功已经在干预前的有效相机帧中出现。
3. 滑落发生在相机缺失之前，避免把不可见瞬时干预误称为记忆推理。
4. 首个盲区 query 的机器人本体状态最大绝对差不超过预设阈值。
5. control 的物体位移为零，slip 的位移固定且可重放。
6. oracle 只用于构造和审计干预，不输入策略。

当前 `controlled_slip_protocol.py` 已实现上述配对记录与机器检查，并通过合成接口 smoke。下一步必须在 LIBERO 中实现物体位姿干预，再用少量 episode 检查接触稳定性与状态匹配；通过前不扩大到正式种子。
